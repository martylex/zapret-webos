# Совместимость

## Нужен ли отдельный IPK для каждого телевизора?

Для совместимых телевизоров используется один IPK. Внутри находятся веб-интерфейс
и Python-код; в нём нет встроенного IP-адреса, пароля или конфигурации конкретного ТВ.
Приложение определяет каталог установки, исходящий интерфейс и локальный IPv4-адрес
во время работы. Строгий `rp_filter` учитывается автоматически начиная с 0.2.1.

Обычно пользователю достаточно установить пакет и выбрать стратегию в интерфейсе.
Если на модели отсутствует нужная библиотека, Python, TUN или подходящий интерфейс,
может потребоваться портирование. Один выбор стратегии такой недостаток не исправит.
Изменять код с помощью агента каждому пользователю не требуется.

## Требования текущей версии

| Требование | Зачем нужно / проверенная конфигурация |
| --- | --- |
| LG webOS с root | Доступ к TUN, raw sockets и маршрутам; Developer Mode без root недостаточно |
| Homebrew Channel с root-службой | `org.webosbrew.hbchannel.service/exec` должен выполнять команды с UID 0 |
| `/usr/bin/python` | Проверен Python 2.7.12; автоматический выбор другого интерпретатора не реализован |
| Python-модули | `ctypes`, `fcntl`, `socket`, `struct`, `select`, `subprocess`, `json`, `hashlib`, `hmac` и стандартные служебные модули |
| Linux TUN | `/dev/net/tun` и поддержка создания временного интерфейса |
| Сетевые сокеты | IPv4 raw sockets; AF_PACKET для обратного пути на ядрах со строгим `rp_filter` |
| Команда `ip` | Просмотр маршрутов и создание временных маршрутов/интерфейса |
| Подключение | IPv4 через `wlan0` или `eth0`, без другого VPN и split-default маршрутов |
| OpenSSL | Для QUIC v1 используется `libcrypto.so.1.0.0` с AES-GCM; без неё QUIC-разбор выключается, TCP может работать |
| Автозапуск | Для запуска при загрузке требуется работающий startup-механизм webOSbrew |

Метка `Architecture: all` означает отсутствие отдельного машинного бинарного файла
приложения. Она не устраняет зависимости от Linux ABI, TUN, интерпретатора,
библиотек и IPC-службы прошивки. Поддержка Python 3, MIPS, ARM64, новых имён
сетевых интерфейсов и других ABI этим релизом не подтверждена. Значение `TUNSETIFF`
в коде проверено на ARM32; для других ABI может понадобиться изменение.

## Проверенные телевизоры

| Модель | Система | Подтверждённый результат |
| --- | --- | --- |
| 60UM7100PLB | ARM32, SDK 4.10.0, прошивка 05.40.97, Linux 4.4.84, Python 2.7.12 | Служба 0.2.0, выбор стратегий и воспроизведение YouTube |
| 32LM6350PLA | ARM32, SDK 4.10.0, прошивка 05.40.97, Linux 4.4.84, Python 2.7.12 | Служба 0.2.1, воспроизведение YouTube, обратный путь со строгим `rp_filter` |

На первом телевизоре отсутствовал рабочий Netfilter/NFQUEUE; на втором был включён
строгий reverse-path filtering. Даже устройства с одинаковым номером прошивки
могут иметь разные ядра. Общая сеть не уравнивает эти различия.

## Что проверить до установки

1. Узнайте точную модель и версию прошивки в настройках ТВ.
2. Проверьте возможность root по [базе совместимости](https://cani.rootmy.tv/)
   и [инструкции webOSbrew](https://www.webosbrew.org/rooting/).
   IPK сам root не устанавливает.
3. Убедитесь, что Homebrew Channel показывает рабочий root. Его
   [служба выполнения команд](https://github.com/webosbrew/webos-homebrew-channel#interfaces)
   может существовать и без root, но тогда прав для приложения не хватит.
4. На новой модели выполните через SSH от root:

```sh
id
uname -m
/usr/bin/python -V
ls -l /dev/net/tun
ip route get 1.1.1.1
/usr/bin/python -c 'import ctypes, fcntl, socket, struct, select, subprocess, json, hashlib, hmac; print("Python modules OK")'
/usr/bin/python -c 'import ctypes; lib=ctypes.CDLL("libcrypto.so.1.0.0"); print(lib.EVP_aes_128_gcm)'
```

Эти команды не меняют сетевую конфигурацию. Наличие `/dev/net/tun` само по себе
не доказывает возможность его настройки; окончательная проверка происходит
при запуске службы. Удалите локальные адреса из вывода перед публикацией.

## Границы проверки

Подтверждены пакетные проверки, подключения к нескольким видеосерверам,
жизненный цикл службы и пользовательское воспроизведение на двух устройствах.
Это не гарантия для всех видео, провайдеров и моделей. Проблема может относиться
к стратегии, серверу, IPv6 или платформе; эти случаи нужно различать при диагностике.
